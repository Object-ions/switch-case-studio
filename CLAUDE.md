## Review fixes → rules
<!-- One line per fix: what broke in review → the rule it becomes. Newest on top. -->
- **Verify a library's integration story in `node_modules`, not from training data.** SSG recon claimed vite-react-ssg uses unhead; it actually uses react-helmet-async — but bundles 1.x against the repo's 3.0.0. Two helmet copies = two React contexts = the SSG head collector silently misses the app's tags (no error, just tag-less static HTML). When a tool wraps a dep the app also uses directly, check `npm ls` for duplicate instances and route through the tool's shared provider/import.
- **vite-react-ssg injects jsdom globals before rendering — a build that doesn't crash is NOT proof of SSR-safety.** `document.body` portals and module-level `matchMedia` "work" under the shim while still producing wrong/divergent HTML. The signals that matter: React server warnings (`useLayoutEffect does nothing on the server`) and hydration mismatches in the browser. Also: `vite preview` serves 200 + fallback HTML for *any* path — verify routes against the emitted files in `build/`, never by status code.
- **CJS deps imported with named ESM imports must be in `ssr.noExternal`.** gsap (`import { ScrollTrigger } from 'gsap/ScrollTrigger'`) left external crashes the SSG's Node render with "Named export not found" — bundling through Vite's SSR transform fixes the interop. See `vite.config.js`.
- **Never render CSS as a JSX text child of `<style>` — use `dangerouslySetInnerHTML`.** The server renderer HTML-escapes text children (quotes → `&#x27;`) while the client doesn't; the resulting hydration text mismatch made React discard the entire server-rendered home page (errors #418/#425/#422 — invisible in dev, which client-renders). Found via a dev-mode SSG build (`vite-react-ssg build --mode development`) to get unminified React errors; verify hydration with a real browser console on the PRODUCTION build, every route.
- **No browser globals at module scope or in first-paint render paths — SSG renders in Node.** Module-level `window`/`document` crashes the build (`createPortal(…, document.body)` in a render body, `useGLTF.preload` at import). `typeof window` guards stop the crash but invite the second failure: branching above-the-fold render output on `window`/`matchMedia` → hydration mismatch → React discards the server HTML → the LCP win is gone. Environment checks live in effects; render output must be environment-independent.
- **Route-variable head tags live ONLY in `src/components/util/Seo.js` — never in `index.html`.** react-helmet-async can't remove static tags, so a static canonical/description in index.html *duplicates* the per-route one (two canonicals = Google picks at random; this shipped for weeks). Every route must render `<Seo>` — without it the previous route's title leaks and no canonical ships. index.html keeps only site-wide constants (favicons, og:image fallback for non-JS social scrapers, Organization/WebSite JSON-LD).
- **`public/sitemap.xml` is generated — never hand-edit.** `scripts/generate-sitemap.mjs` (runs on `prebuild`) derives URLs from `projects.json`/`services.json`; hand edits get overwritten and drift (birth-of-venus was routable but missing).
- **One `h1` per page; reusable sections take a `headingTag` prop.** Decorative text effects (TextPressure, marquee) had hardcoded `h1`s — home shipped 5. A section used both standalone (/contact) and embedded (home) renders `h1` only standalone (`<Contact headingTag="h1" />`).
- **When a breakpoint changes a component's layout mode, re-place its absolutely-positioned decorations.** The tile badge (`position: absolute; top/left`) was placed for the desktop card; the ≤768px tile switches to a compact `image | text` grid and the badge landed on the title. Corner-pinned overlays only work relative to one layout — at the breakpoint, either put them in flow (own grid row, like `.tile-badge` mobile) or re-anchor them. See `_projects-tiles.scss`.
- **Every text section caps at `$max-width` (1200px, `_variables.scss`), centered.** The services list spanned the full window on wide screens — title far left, CTA far right. The variable existed; the section never used it. New sections get `max-width: $max-width; margin-inline: auto` from the start; full-bleed is for backgrounds, not text. See `services.scss` `&__menu`.
- **A scroll reveal must never be able to leave content invisible.** Case-study tiles intermittently rendered dim/near-invisible in production (corner tiles worst, which tile varied per load). Cause: `gsap.fromTo('.tile', {autoAlpha:0}, {…, scrollTrigger, once:true})` — `fromTo`'s `immediateRender` re-applies the hidden "from" state whenever *any* component calls `ScrollTrigger.refresh()` during initial font/image load, catching the center-out stagger mid-flight. Rules: (1) set the hidden start with `gsap.set`, not `fromTo` immediateRender; (2) reveal via `ScrollTrigger.create({onEnter})`; (3) `ScrollTrigger.refresh()` after lazy `loading="lazy"` images load (they shift layout after `start` is measured); (4) reveal immediately if already in view at mount (an already-past `once` trigger won't fire `onEnter`); (5) always add a timed safety net (`gsap.delayedCall`) that forces full opacity. See `src/components/ProjectsTiles.js`. Verify by hard-reloading several times + throttled network, capturing real pixels.
- **Data-driven tiles render conditionally — never ship an empty placeholder box.** The bento `ProjectPage` supports 5 media slots (desktop/mobile/hero-detail/copy-block/CTA-form) + variable metrics, but most projects only have 2 images. Each tile is built from data and filtered out when its field is absent (`[...].filter(Boolean)`), and section wrappers gate on `hasResults`/`hasSummary`/`galleryTiles.length`. The gallery uses `data-count` so it reflows (1 tile = full width, 2–3 = lead + stack) instead of leaving holes. Add optional fields (`mediaMobile`, `mediaCopy`, `mediaCta` + `*Alt`) to `projects.json` and the slot lights up; omit it and it stays hidden.
- **Vite does NOT rewrite `url()` asset refs pulled in through a Sass `@import`.** Post-CRA, the `@font-face` in `src/styles/_variables.scss` kept `url('../assets/fonts/…')`; the build emitted a hashed font but left the CSS path unrewritten ("didn't resolve at build time" warning), so it 404'd → Netlify's SPA `/*→/index.html` fallback served HTML with `Content-Type: text/html` → NeueMachina silently fell back to sans-serif. A 200 status hid it; only content-type exposed it. Fix = serve such fonts from `public/` with a root-absolute path (`url('/fonts/…')`), like images/models already are. Verify font/asset paths by content-type, not status code.
- **Verify UI rendering with real pixels, not computed styles.** A `getComputedStyle`/`elementFromPoint` probe reported "no white flash" while the user saw one — because a page's `background` reads `#000` regardless of an ancestor's animated opacity. Only a CDP screencast (actual composited frames) caught it. For paint/flash/animation bugs, capture pixels.
- **On a mixed light/dark SPA, a page that fades in must sit on a backdrop matching its own theme.** `<body>`/`<main>` are light grey but most pages paint `#000`; fading a page from opacity 0 let the light parent flash through. Fix = per-route `.route-backdrop` (`.is-dark` default, `.is-light` for legal + `/pricing/:slug`). See `src/App.js` `LIGHT_ROUTES`.

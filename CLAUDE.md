## Blog (`/blog`, `/blog/:slug`) — data contract, do not break

The blog is data-driven from `src/data/posts.json` and pre-rendered per post via `getStaticPaths`
in `routes.js`. It's the publish target for the **Studio Journal Factory** (Beau writes weekly,
commits `posts.json`, pushes → Netlify deploys). Pages: `BlogPage.js` (list) + `BlogPostPage.js`
(article), styles `blogPage.scss` / `blogPostPage.scss` (dark, reuse the existing tokens; list is
`projectsPage` parity, article is a 760px reading column).

- **A post is a flat object** with a `body` array of blocks; block `type` ∈ `paragraph` |
  `heading` | `list` (items[]) | `quote` (text, cite?) | `video` (url, caption?/title?).
  `video` embeds a YouTube URL (watch/share/shorts/embed all accepted) as a lazy, responsive
  16:9 `youtube-nocookie` iframe — embedding only, no video files hosted. Unknown types render
  nothing (safe).
  Required: `slug` (unique kebab), `title`, `excerpt`, `category`, `body`. The rest have defaults.
- **Never hand-edit `posts.json` from an automation** — insert via `node scripts/add-post.mjs
  <post.json>` (validates schema + unique slug, fills date/readingTime/author, inserts newest-first,
  rejects malformed posts). Adding a block type means updating BOTH `add-post.mjs`'s `BLOCK_TYPES`
  and `BlogPostPage.js`'s `Block` switch, or posts using it silently render blank.
- `coverImage` is optional — the list card shows a branded gradient stand-in when it's empty (so
  automation posts with no art don't read as broken). The article omits the cover figure entirely.
- The sitemap generator (`generate-sitemap.mjs`) already emits `/blog` + every post; it derives
  from `posts.json`, so new posts appear automatically. Both pages render `<Seo>` (Blog /
  BlogPosting + breadcrumb JSON-LD) — keep that.

## Review fixes → rules
<!-- One line per fix: what broke in review → the rule it becomes. Newest on top. -->
- **Only `<h1>` uses the display face (`$font-special`, SCS Display); every other heading/text uses `$font-text` (Inter).** SCS Display is a tight decorative face that collides and reads as messy at h2/h3 sizes and in body-ish utility text (kickers, numbers, prices) — legible only at hero-h1 scale. There's NO global `h1{font-family}` rule; each component sets its own font, so the policy is enforced per selector: new headings default to `$font-text`, and `$font-special` is reserved for the single page/hero `<h1>`. When a component's heading tag is dynamic (`headingTag` prop — e.g. `.contact-right__heading` is h2 in the home section, h1 on `/contact`), scope the display face to the h1 case only: base = `$font-text`, then `@at-root h1#{&} { font-family: $font-special; }` (NOT `h1&` — Dart Sass rejects `&` mid-compound). Two deliberate exceptions kept as display because they're logo-style brand marks, not readable headings: the footer wordmark (`.footer-wordmark__text`, giant outlined "switch case") and the About marquee (`.marquee`). Verify in the COMPILED split CSS (per-component files) that h1 selectors resolve to `SCS Display` and all else to `Inter`.
- **Dead-code sweeps: prove death, then prove the removal changed nothing.** (Legacy cleanup 2026-06-10, protocol: `.audit/cleanup-protocol.md`.) Unimported SCSS emits no CSS (no Sass `additionalData` here) — delete it and confirm the content-hashed build output is unchanged. For selectors inside live files: extract class names from the COMPILED css (nesting resolved), string-check against src — but "no grep hit" only counts after reviewing dynamic construction (`.replace(/\.webp$/,'')-256.webp` srcsets, Sass `Inter-#{$w}` url interpolation, library-injected classes like `.typed-cursor`). Verify by class-set diff: removed exactly the flagged names, added none. CRA fossils lived OUTSIDE src too (all removed by the merged 2026-06 cleanup — the stack is now Vite 7 + vite-react-ssg with zero CRA residue in live files): stock `public/manifest.json`, `.unimportedrc.json` ignore-listing long-removed deps — and `public/` ships everything in it, so source artifacts (the unsubsetted display OTF) don't belong there (→ `fonts-src/`).
- **A `! grep -q` sweep that flags ~100% positives is a broken sweep, not a dead codebase.** BSD grep exits 2 when ANY path arg doesn't exist — even with matches — so one bad path made every class look dead. The bad path (`src/App.js`) came from THIS file citing it after the rename to `routes.js`: when a file referenced here is renamed, update its mentions here in the same commit — doc rot misleads the next audit (human or AI).
- **A licensed component does NOT license the assets it references — verify font/asset provenance separately.** TextPressure (React Bits / CodePen port) is properly licensed, but it hotlinked `CompressaPRO-GX.woff2` from `res.cloudinary.com` — a separately-licensed commercial typeface that was never ours to ship. "The component is licensed" says nothing about the fonts/images/media its props point at. Audit every referenced asset's own license; for fonts prefer self-hosted OFL faces (here: Compressa → self-hosted Roboto Flex, OFL-1.1, latin-subset VF with the wght/wdth/slnt axes the warp needs). Swapping a variable font means remapping the effect's axis tags + ranges to the new font (Compressa `'ital' 0–1` had no equivalent → Roboto Flex `'slnt' 0→-10`; tune to the new font's extremes, e.g. wght floor 300 not 100 so the resting state isn't hairline).
- **A third-party/non-critical resource loaded in the LCP window can gate LCP even when the LCP element itself isn't blocked — defer it past LCP.** Mobile LCP was 6.2s with the LCP element being the *preloaded NeueMachina headline* (not font-blocked) — yet a hotlinked Cloudinary font fetch (~733ms, non-preconnected) sat serialized on the critical request chain, and gtag.js (155KB) loaded at hydration. Removing the third-party font from the initial load (IO-gate the component that injects its `@font-face`, MoonSlot pattern) + deferring gtag.js to `requestIdleCallback` dropped LCP 6.2→2.9s. Rules: (1) nothing on the critical chain that isn't needed for first paint — lazy-mount below-fold components so their fonts/scripts never enter the initial load; (2) defer analytics/3rd-party scripts to idle, but keep their *synchronous* setup (gtag stub + Consent Mode `default` + `config`) so the dataLayer queue preserves the cookieless `gcs=G100` ping and live consent updates — only the network fetch moves. Verify the consent chain end-to-end on prod after (G100 → Accept → G111 → conversion).
- **`React.lazy` code-splits but does NOT defer — rendering the lazy component fires the import at hydration.** The 990KB Three.js Moon chunk fetched+parsed during the mobile LCP window with zero scrolling. Decorative below-fold heavies need the IMPORT gated behind an IntersectionObserver (`rootMargin` ~200px) with a fixed-size CSS slot so mounting can't shift layout. See `About.js` `MoonSlot`.
- **Animation loops: batch reads-then-writes, gate by visibility+input, stop on convergence.** TextPressure's RAF loop interleaved `getBoundingClientRect` per char with style writes — a forced layout per character per frame, running from hydration, below the fold, on touch devices, forever (PSI's 109/78/62ms forced-reflow entries). Rules: (1) read ALL rects, then write ALL styles — one layout flush per frame; (2) IO-gate the loop, skip it entirely on `hover: none`/reduced-motion (one batched pass reproduces the converged static look); (3) settle-stop when the *smoothed value converges* (mouse≈cursor) — NOT "no styles changed": clamped outputs read as falsely calm mid-flight and kill the loop early; (4) never compare against `style.fontVariationSettings` read-back — CSSOM normalizes quotes/numbers so `!==` is always true; cache what YOU wrote. See `TextPressure.js`.
- **Headless verification: `scrollIntoView` is a silent no-op under `scroll-behavior: smooth`** — three "failures" were the page never scrolling. Scroll with `window.scrollTo({behavior:'instant'})` and assert `scrollY` moved before trusting any visibility-gated result.
- **Fonts: self-host, latin-subset woff2, `font-display: swap`, preload ONLY the hero face.** The Google css2 link served 31+ cross-origin files (6 weights × 7 subsets — cyrillic/greek/vietnamese nobody uses); self-hosted latin statics = 7 same-origin files (~155KB total, NeueMachina 59KB OTF → 10KB woff2). Caveats learned: (1) **CloudConvert converts format but does NOT subset** — the "converted" woff2 carried all 549 glyphs; re-subset with `pyftsubset --unicodes=U+0000-00FF --flavor=woff2` (verify `×` U+00D7 survives — it's in the copy). (2) **Declared weights must exist as files** — weights 100/200/900 were declared but never loaded, silently snapping to 300/800; fix declarations, don't ship extra files. (3) **Statics over the variable font when out-of-range declarations existed** — a variable font would render those true-thin/true-black, changing how the site has always looked. (4) `@font-face` lives in `app.scss` (imported once), NEVER in `_variables.scss` — emitted CSS in a 40×-imported partial ships 20 duplicate copies. (5) Preloading the hero face removed it from CLS causes; non-preloaded faces still swap-shift — next lever is metric-compatible fallbacks (`size-adjust`), not preloading everything.
- **typed.js / cycling-text slots need a reserved width (ch units for monospace) or they shift layout once content paints early enough to be measured.** The hero verb cycle reflowed the headline every word (desktop CLS 0.177 — invisible pre-SSG because nothing painted until LH stopped watching). Fix: `display:inline-block; min-width: <longest word>ch; text-align:left` on the typed target span, computed inline from the STRINGS array so it can't drift (`WelcomeTyped.js`). Verify with element positions across cycles, not just the score — a second CLS cause (font swap) can hide behind the first.
- **`netlify deploy` BUILDS by default (CLI v17+) and injects the site's env vars — drafts are faithful to prod, and your local `build/` gets overwritten by that env-injected build.** This is why a "local" bundle suddenly contained the GA ID (`VITE_GA_MEASUREMENT_ID` lives only in Netlify's site env): the CLI rebuilt before uploading. Corollaries: a clean local `npm run build` produces a GA-less bundle (expected, not a bug); draft/preview deploys carry `X-Robots-Tag: noindex` by design, so Lighthouse SEO drops to ~69 on drafts via `is-crawlable` — only that audit; prod is unaffected.
- **Verify a library's integration story in `node_modules`, not from training data.** SSG recon claimed vite-react-ssg uses unhead; it actually uses react-helmet-async — but bundles 1.x against the repo's 3.0.0. Two helmet copies = two React contexts = the SSG head collector silently misses the app's tags (no error, just tag-less static HTML). When a tool wraps a dep the app also uses directly, check `npm ls` for duplicate instances and route through the tool's shared provider/import.
- **vite-react-ssg injects jsdom globals before rendering — a build that doesn't crash is NOT proof of SSR-safety.** `document.body` portals and module-level `matchMedia` "work" under the shim while still producing wrong/divergent HTML. The signals that matter: React server warnings (`useLayoutEffect does nothing on the server`) and hydration mismatches in the browser. Also: `vite preview` serves 200 + fallback HTML for *any* path — verify routes against the emitted files in `build/`, never by status code.
- **CJS deps imported with named ESM imports must be in `ssr.noExternal`.** gsap (`import { ScrollTrigger } from 'gsap/ScrollTrigger'`) left external crashes the SSG's Node render with "Named export not found" — bundling through Vite's SSR transform fixes the interop. See `vite.config.js`.
- **Never render CSS as a JSX text child of `<style>` — use `dangerouslySetInnerHTML`.** The server renderer HTML-escapes text children (quotes → `&#x27;`) while the client doesn't; the resulting hydration text mismatch made React discard the entire server-rendered home page (errors #418/#425/#422 — invisible in dev, which client-renders). Found via a dev-mode SSG build (`vite-react-ssg build --mode development`) to get unminified React errors; verify hydration with a real browser console on the PRODUCTION build, every route.
- **No browser globals at module scope or in first-paint render paths — SSG renders in Node.** Module-level `window`/`document` crashes the build (`createPortal(…, document.body)` in a render body, `useGLTF.preload` at import). `typeof window` guards stop the crash but invite the second failure: branching above-the-fold render output on `window`/`matchMedia` → hydration mismatch → React discards the server HTML → the LCP win is gone. Environment checks live in effects; render output must be environment-independent.
- **Route-variable head tags live ONLY in `src/components/util/Seo.js` — never in `index.html`.** Since SSG, every page's title/description/canonical/og/twitter is baked into its static HTML at build time (injected after `<head>` from `<Seo>`); a static copy in index.html ships in EVERY built file as a duplicate (two titles/og:titles = scrapers and Google pick at random — happened with the old "non-JS scraper fallback" block, now obsolete and removed: scrapers get real per-route tags without JS). index.html keeps only true site-wide constants: favicons, `og:site_name`/`og:locale`, Organization/WebSite JSON-LD, fonts, manifest — and NO static `<title>`. Every route must render `<Seo>`.
- **`public/sitemap.xml` is generated — never hand-edit.** `scripts/generate-sitemap.mjs` (runs on `prebuild`) derives URLs from `projects.json`/`services.json`; hand edits get overwritten and drift (birth-of-venus was routable but missing).
- **One `h1` per page; reusable sections take a `headingTag` prop.** Decorative text effects (TextPressure, marquee) had hardcoded `h1`s — home shipped 5. A section used both standalone (/contact) and embedded (home) renders `h1` only standalone (`<Contact headingTag="h1" />`).
- **When a breakpoint changes a component's layout mode, re-place its absolutely-positioned decorations.** The tile badge (`position: absolute; top/left`) was placed for the desktop card; the ≤768px tile switches to a compact `image | text` grid and the badge landed on the title. Corner-pinned overlays only work relative to one layout — at the breakpoint, either put them in flow (own grid row, like `.tile-badge` mobile) or re-anchor them. See `_projects-tiles.scss`.
- **Every text section caps at `$max-width` (1200px, `_variables.scss`), centered.** The services list spanned the full window on wide screens — title far left, CTA far right. The variable existed; the section never used it. New sections get `max-width: $max-width; margin-inline: auto` from the start; full-bleed is for backgrounds, not text. See `services.scss` `&__menu`.
- **ScrollTrigger `once:true` + already-past start: do NOT assume whether `onEnter` fires at creation — instrument and count.** Two contradictory in-repo observations exist: the CaseStudyTiles rule below recorded "an already-past `once` trigger won't fire `onEnter`" (2026-06, mid-page tiles, refresh()-heavy load), while LC-26a measured the opposite — a trigger created at hydration on a top-of-route header (start already passed at creation) fired `onEnter` during creation on every cold load (3× instrumented, count=1 at 353–1035ms; a manual in-view fallback would have double-fired and produced a visible mid-stagger restart). The condition separating the two behaviors (creation timing vs settled layout vs refresh/scroll-restoration interplay) is NOT established — so when writing a reveal: instrument the reveal callback, count calls on a cold load of the real build, and only then decide whether a fallback is needed; if one is, make `reveal()` idempotent (guard flag) rather than trusting either clause. Safety nets must also check `gsap.isTweening(target)` before re-firing — `opacity < 1` alone restarts a healthy in-flight reveal.
- **A scroll reveal must never be able to leave content invisible.** Case-study tiles intermittently rendered dim/near-invisible in production (corner tiles worst, which tile varied per load). Cause: `gsap.fromTo('.tile', {autoAlpha:0}, {…, scrollTrigger, once:true})` — `fromTo`'s `immediateRender` re-applies the hidden "from" state whenever *any* component calls `ScrollTrigger.refresh()` during initial font/image load, catching the center-out stagger mid-flight. Rules: (1) set the hidden start with `gsap.set`, not `fromTo` immediateRender; (2) reveal via `ScrollTrigger.create({onEnter})`; (3) `ScrollTrigger.refresh()` after lazy `loading="lazy"` images load (they shift layout after `start` is measured); (4) reveal immediately if already in view at mount (an already-past `once` trigger won't fire `onEnter`); (5) always add a timed safety net (`gsap.delayedCall`) that forces full opacity. See `src/components/sections/CaseStudyTiles.js`. Verify by hard-reloading several times + throttled network, capturing real pixels.
- **Data-driven tiles render conditionally — never ship an empty placeholder box.** The bento `ProjectPage` supports 5 media slots (desktop/mobile/hero-detail/copy-block/CTA-form) + variable metrics, but most projects only have 2 images. Each tile is built from data and filtered out when its field is absent (`[...].filter(Boolean)`), and section wrappers gate on `hasResults`/`hasSummary`/`galleryTiles.length`. The gallery uses `data-count` so it reflows (1 tile = full width, 2–3 = lead + stack) instead of leaving holes. Add optional fields (`mediaMobile`, `mediaCopy`, `mediaCta` + `*Alt`) to `projects.json` and the slot lights up; omit it and it stays hidden.
- **Vite does NOT rewrite `url()` asset refs pulled in through a Sass `@import`.** Post-CRA, the `@font-face` in `src/styles/_variables.scss` kept `url('../assets/fonts/…')`; the build emitted a hashed font but left the CSS path unrewritten ("didn't resolve at build time" warning), so it 404'd → Netlify's SPA `/*→/index.html` fallback served HTML with `Content-Type: text/html` → NeueMachina silently fell back to sans-serif. A 200 status hid it; only content-type exposed it. Fix = serve such fonts from `public/` with a root-absolute path (`url('/fonts/…')`), like images/models already are. Verify font/asset paths by content-type, not status code.
- **Verify UI rendering with real pixels, not computed styles.** A `getComputedStyle`/`elementFromPoint` probe reported "no white flash" while the user saw one — because a page's `background` reads `#000` regardless of an ancestor's animated opacity. Only a CDP screencast (actual composited frames) caught it. For paint/flash/animation bugs, capture pixels.
- **A CSS percentage transform poisons GSAP `xPercent` tweens — `gsap.set({x: 0, xPercent: …})` when taking over a CSS-positioned element.** The SSG-friendly `transform: translateX(100%)` base on the mobile menu panel is parsed by GSAP via `getComputedStyle`, which returns a resolved PIXEL matrix — GSAP cached `x: <panelWidth>px, xPercent: 0`, and every later `xPercent` tween *added to* that stale pixel offset: the open animation ran 200%→100%, offscreen→offscreen, while the Menu/Close button (no CSS-base transform) animated fine — menu looked dead on every phone. Corollary: when a commit moves an element's initial state from JS to CSS (here: to silence an SSR warning), re-test the JS that animates *from* that state, on the layout where it runs (mobile). See `StaggeredMenu.js`.
- **On a mixed light/dark SPA, a page that fades in must sit on a backdrop matching its own theme.** `<body>`/`<main>` are light grey but most pages paint `#000`; fading a page from opacity 0 let the light parent flash through. Fix = per-route `.route-backdrop` (`.is-dark` default, `.is-light` for legal + `/pricing/:slug`). See `src/routes.js` `LIGHT_ROUTES`.
- **Overlapping/colliding letters that CSS can't fix = bad glyph ADVANCES in the font, not a CSS bug.** A GlyphrStudio batch transform scaled some SCS Display outlines ~2.1× but left their `hmtx` advances at the old small values, so ink ran hundreds of units past the advance (large negative right side bearing) and the next glyph started on top of it — `b x u q z r " * / ? |` were hit; `o e a H` (advance scaled too) were fine. size-adjust can't fix this (it scales the whole font uniformly; the ink/advance ratio is intrinsic). Fix = `scripts/fix_font.py` (metrics-only, never touches outlines): per glyph `advance = inkXmax + TARGET_RSB`, `lsb = inkXmin`, bounds-based NOT a blind ×2.1. Tune `TARGET_RSB` to the face's own rhythm (here 27 = median RSB of the correctly-scaled glyphs; 80 read ~3× too loose). The script's verify pass re-opens the SAVED file and sweeps the ENTIRE glyph order asserting `xMax <= advance` (tol 0), exits non-zero on FAIL — run it and confirm PASS on every re-export before subsetting. This font has no `kern`/`GPOS`, so spacing is 100% advance-driven. Ship a NEW woff2 filename (`-v2`) + update both `@font-face` src and the index.html preload, so cached broken bytes aren't served.
- **`security.txt` (`public/.well-known/security.txt`, RFC 9116) has an `Expires` date that MUST be bumped before it passes — a past `Expires` invalidates the whole file (scanners reject it).** Currently `2027-06-17`; when bumping, also confirm the `Contact`/`Canonical` still hold. The file is hand-authored (NOT generated like `sitemap.xml`); Vite 7's `copyDir` copies the dotfolder to `build/.well-known/` unchanged (verified byte-identical), so no build/Netlify config is involved — just edit the static file.
- **SCSS `$variables` don't cross `@use` module scope — export shared tokens as `:root` custom properties.** The motion tokens compiled fine in `@import`-era partials but broke `footer.scss` (`@use '../mixins' as *`) with "Undefined variable": a `@use`d module resolves variables lexically, and adding `@use './variables'` inside `_mixins.scss` isn't an option while `app.scss` still `@import`s it (a file containing `@use` can't be `@import`ed). Pattern: define the SCSS token once in `_variables.scss`, export it once in `app.scss` (`:root { --dur-fast: #{$dur-fast}; }`), and have shared mixins consume `var(--dur-fast, fallback)`. Works under both module systems.
- **The CSS-percentage-transform poison strikes on the FIRST new-axis tween, even years after the original code shipped.** (Corollary to the StaggeredMenu rule.) The stripe orb (CSS `translate(-50%,-50%)`, GSAP x-drift) worked for months — adding a `yPercent` scrub dropped it 210px because the parsed pixel matrix carries no percent components. The cursor dot had the same bug live (corner-anchored by 12.5px) since its first `x/y` tween. When ANY GSAP tween touches an element that has a CSS transform, make GSAP claim the full transform up front (`gsap.set({xPercent:…, yPercent:…, x:…, y:…})`) and give reduced-motion paths `clearProps:'transform'` so the CSS state returns. Audit every existing tween target for this before adding a tween on a new axis.
- **motion/react's `initial="hidden"` is SERVER-RENDERED — whileInView entrances bake `opacity:0` into SSG HTML.** The pricing h1 was invisible without JS (found during VE-8; AboutPage/ReviewsPage share `motionVariants` and likely do the same — unaudited). The never-invisible rule therefore prefers the GSAP house pattern for entrances on SSG routes: static HTML ships visible, `gsap.set` hides at runtime only. If motion/react variants must be used for an entrance, verify the emitted `build/*.html` carries no inline hidden state.
- **An occluded automation window freezes CSS transitions AND the GSAP ticker — only END states are verifiable agent-side.** (Extends the RAF-suspension note.) `getComputedStyle` mid-"animation" returns the start value forever; even inline-style writes appear ignored while a transition is attached (probe with `transition:none` to see the real resolved value). Screenshots force frame production and advance animations between captures. Verify animated UI by (1) probing the tween's end state with transitions disabled, (2) asserting the rule matches (`el.matches(':hover')`, cssRules scan), and (3) settled screenshots — never by watching intermediate values; the owner's visible-window pass is the authoritative check for motion feel.
- **motion/react `whileInView` with a `viewport.amount` threshold STRANDS tall sections that can't clear the threshold on load — the taller the section, the more absolute scroll must be in view.** `/projects` + `/testimonials` grids used `whileInView` `amount:0.1`; the grid is very tall (single-column on mobile = taller still), so 10% of it is a large pixel distance that never clears the fold on a phone → the IntersectionObserver never fires → every card stays at the SSR-baked `opacity:0` → the page reads as EMPTY until you scroll (the short `amount:0.3` headers revealed fine, so only the heading showed — a classic "header but no content" mobile bug). Fix: primary content that sits in the first viewport must reveal on MOUNT, not on scroll — use `animate="visible"` (fires on hydration regardless of scroll position), not `whileInView`. Reserve `whileInView` for content genuinely below the fold. Verify by measuring card opacity at a true mobile width, not desktop (the threshold math flips with column count). Corollary to the "motion/react SSRs `initial=hidden`" rule: `animate` still bakes `opacity:0` into the HTML (brief pre-hydration flash on non-LCP pages, acceptable), but it can't STRAND because it doesn't depend on a scroll event that may never come.
- **Every package imported at runtime must be declared in `dependencies` — transitive hoisting is not a declaration.** (Batch LC-19/20, 2026-07-21: `prop-types` was imported by live `ScrollingShot.js` but supplied only by four hoisting parents; `vite-react-ssg` — imported in `src/index.js` + `Seo.js`, i.e. the app's hydration + head glue — sat in devDependencies.) When reclassifying, judge the lockfile diff by COMPOSITION, not size: a devDeps→deps move legitimately cascades `"dev": true` removals across the whole transitive tree, and npm may also prune unrequested optional-peer entries environmentally — attribute that churn by control-testing `npm install` on unmodified HEAD before blaming the edit. For client-gated components (`{liveOK && …}` behind image-preload/mount state), verify no-regression via build-artifact content hashes, not rendered-HTML presence — they are never in static output.
- **Route-count verification: count emitted files (`find build -name '*.html' | wc -l`), never grep the build log** — the client build prints `build/index.html` (the pre-render shell asset, ~4KB) before the SSG "Rendering Pages" list prints the real one (~71KB), so a log grep double-counts. Baseline 2026-07: 31 HTML files (28 sitemap URLs + `/30-off` + `/partners` + `404`).
- **The "mobile feels more static than desktop" complaint is usually NOT a perf downgrade — it's that the reactive layer is pointer-only.** The custom cursor, the hero cursor-field (CursorWave), MagneticButton, TextPressure's cursor-warp, and every hover-lift (tiles, service-row wipe, card lifts) require a cursor and physically cannot run on touch. The only genuinely perf-motivated mobile gates are the IO-deferred 3D Moon (~1MB) and the tile particle/spotlight effects (off on mobile). Touch's equivalent of hover is the `:active` press — give it a scoped `@media (hover:none) and (pointer:coarse)` opacity press (opacity, not transform, so it never fights GSAP/motion-owned transforms; a CSS transform would be overridden by their inline transform or conflict). Also check whether the phone has iOS "Reduce Motion" on — that strips nearly everything by design.
